### Shell flags

- **`--jit-opt=20 --jit-threshold=20`**: the configuration every goal is measured in (the
  baseline tier plus the optimizer).
- **`--jit-opt`**: the optimizer with default thresholds.
- **`--jit-baseline`**: the baseline tier alone.
- **`--jit --jit-calls`**: entry mode, the optimizer off a baseline frame.
- **`--jit-dump`**: SSA, code bytes, refusals and exits. It prints megabytes, so always filter
  it with `grep`. Lines worth grepping:
  - `jit: optimizing <n> <name> <file>:<line>`: one per compile;
  - `jit: refused: <why>`: a refusal;
  - `jit: left: <fn> <pc> <opcode> ...`: a guard that failed;
  - `jit: optimized code unlinked`: code given back to the baseline tier;
  - `jit: not inlined: ...`: a call site left a call;
  - `jit: cost ... translate-ns ... optimize-ns ... verify-ns ... backend-ns`: compile time.
- **`--jit-stats`**: counters.
- **`--jit-stress=N`**: makes guards fail periodically, but optimized code on a baseline frame
  refuses it (`x64_backend.supported`), so it tests nothing in the default mode.

### Measuring on this kind of VM

- **No hardware counters.** Instruction counts under callgrind are stable; the clock moves 5
  to 10% between runs of one build.
- **Instructions are only a proxy.** Moves between registers cost next to nothing. A value's
  trip through a frame slot does, and so does a taken jump.
- **Crypto's work depends on the clock.** It seeds its random numbers from it, so its
  instruction count varies by up to 8% between runs of one build. For instruction counts,
  prepend this line to the timed script:
  `Date.prototype.getTime = function () { return 1234567890123; };`
- **Telling two builds apart.**
  `python3 modules/jit/prof/bench/ab_shells.py SCRIPT SHELL1 SHELL2 ... --rounds 15` interleaves
  them on one core and prints medians and minimums. The timed scripts come from
  `modules/engine/scripts/v8bench.py`, for example:

  ```sh
  python3 -c "import v8bench; v8bench.script(DIR, ['crypto'], v8bench.FIXED_RUNNER % (v8bench.FIXED['crypto'] * 20), 'timed20-crypto')"
  ```

  Run it in `modules/engine/scripts`. Fixed-work copies of the eight benchmarks at x20 are in
  `modules/jit/prof/bench/fixed/`.
- **Instruction count of a run.**
  `valgrind --tool=callgrind --callgrind-out-file=/dev/null <shell> --jit-opt=20 --jit-threshold=20 script.js 2>&1 | grep refs`
- **Compare like with like.** Compare a release build with a release build (a dev build
  includes the slow dev compiler). Counts also move a few percent with the script path's
  length, so keep the same absolute path.

## 6. How the JIT works (what you need in your head)

**Tiers.** Bytecode runs in the interpreter. A hot function gets baseline code
(`modules/jit/src/baseline*.silk`). A hot baseline function gets optimized code on the same
baseline frame ("frame mode", `x64_lower.lowerOnFrame`), built from SSA:

- `ssa_translate`: bytecode to SSA;
- `ssa_opt`: the passes (`ssa_ownership`, `ssa_opt_borrow`, `ssa_opt_hoist`,
  `ssa_opt_unboxed`, `ssa_shapes`);
- `ssa_verify`: the verifier;
- `x64_regalloc` and `x64_backend`: register allocation and code;
- `x64_exits`: the exit tables.

**Exits.** A guard that fails leaves through a table-driven exit (`x64_exits`,
`jit_exit_state`) and the baseline code goes on. `jit_runtime.noteLeft` remembers the site;
after `EXIT_BURST` exits the code is unlinked, and the next compile keeps the sites that left
general (`sites`). Each recompile learns only the sites that left, one round at a time.

**Registers on a baseline frame** (`x64_regalloc.framePool`). r12 is the BaselineEnv and r13
the runtime header; both are pinned. The pool:

- rbx, r14, r15: kept over calls.
- rsi, rdi, rdx, r10, rcx: fragile. A value takes one only if every instruction of its interval
  keeps them (`keepsFragile`): the gentle ones (integer arithmetic, compares, constants, number
  boxes and unboxes, jumps, branches), `inline.frame` (emits nothing), `check.array` and trusted
  element reads (they leave rather than call), and trusted element stores and polls (their slow
  paths save the five registers around the call, `keepFragile`).
- rax, r8, r9, r11 are the lowering's own. An exit takes how it left in r8. A variable shift
  keeps rcx in r11.

If you change the lowering of an instruction `keepsFragile` names so that it touches a fragile
register, values break silently. Keep the list and the lowering in step.

**Values** live in 16-byte frame slots, `rsp + v * 16`. A spilled i32 is stored zero-extended.

**Ownership.** Every Value is `Owned` (one count, consumed once on every path), `Borrowed` or
`Imm`. The verifier enforces it.

**Trusted element accesses** (`ssa_opt_hoist`):

- One `check.array` per Array goes in front of a loop, and the accesses (`Inst.trusted`) test
  only the index, leaving past the count.
- Conditions: nothing in the loop may change the Array's kind (no calls, stepped reads, field or
  binding stores), and every element store must be trusted.
- A failed check on a baseline frame is remembered as `ssa.SITE_ARRAY` (through
  `jit_exit_state.CODE_ARRAY_CHECK`). The next compile then trusts nothing in that loop but keeps
  its other hoisting.

**Block order** (`Function.compact`, `loopDepths`). Reverse postorder, searching a branch's
successor in fewer loops first, so each loop's blocks follow its header with nothing between.
That keeps the intervals of the values a loop carries short.

**Inlining** (`ssa_translate`, `docs/jit/inlining.md`):

- Method calls whose target the baseline site caches know are inlined, with `check.callee` or
  known-shape guards.
- Inlined bodies may have loops and may write their parameters. A write updates the caller's
  operand in `held`, and every exit after one leaves with the bodies' frames
  (`Translator.paramWrites`).

**More detail:** `docs/jit/optimizer.md`, `docs/jit/code-quality.md` (every code-quality change
with its measurement), `docs/jit/ssa.md`, `docs/jit/baseline.md`, `docs/jit/inlining.md`.

## 7. Traps

**Builds**

- Never edit sources while a build is running, and never run two builds at once.

**Silk**

- `effect` and `run` are keywords: no locals with those names.
- There is no slice syntax (`a[0..7]`).
- `u64.shiftLeft` and `shiftRight` take a u64 right operand.
- OWN0010/OWN0011: compute an argument into a local before a call that borrows the same object
  mutably (for example `let miss = self.exitLabels.get(...)` before `run self.f(miss)`).

**Editing**

- When patching files with Python string replacement, assert that the old text is present and
  count the replacements.

**Machine code**

- AOT must stay possible: refer to engine code through symbols and relocations, not raw
  addresses.
- Assembler branch relaxation moves offsets taken with `offset()`: use `finishPlaced`.
- A stub's slow path assumes the stub's own stack alignment.

**Measuring**

- RegExp interpreter counts have two levels depending on the environment size: rerun with
  `env -i PAD=xxx` at a few lengths before blaming a change.

**HTTP order service.** What remains is runtime work in the first place: native calls from
machine code, JSON, deferred releases. For machine code, the lever is the footprint of cold

calls are spread too thin.
