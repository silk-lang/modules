## How to resume

Setup (READ, `docs/jit/HANDOFF.md` "Starting from nothing"): attach `silk-lang/silk` with push
access or the Silk installer gets HTTP 403 (then stop and ask Julia, no workaround); Silk
0.1.0-dev.74, Clang 22.1.8 (`SILK_CLANG`), Node 24 for `NODE_REFERENCE`, valgrind, jsc.

Gate chain, from `modules/engine`, one heavy command at a time under `timeout`, killing leftover
`silkc` (ppid 1) by PID after each Silk step, never benchmarking while a compiler runs, never two
gates at once (about 100 minutes):

1. `silk test --manifest-path ../jit/silk.toml --no-cache`
2. `(cd ../jit && python3 scripts/encodings.py --check)`
3. `silk build --release`, then `silk build --release --manifest-path ../jit/shell/silk.toml`
4. `python3 scripts/v8bench.py --instructions <previous engine> <new engine>` (regexp is bimodal)
5. each v8 benchmark, fixed iterations (`v8bench.script(dir, [name], FIXED_RUNNER % (FIXED[name]*3), name)`),
   under the JIT shell with `--jit` and `--jit --jit-calls`: exit 0 and output equal to plain
6. `python3 scripts/differential.py --count 3000 --configs plain,observed,jit,jit-stress,jit-calls,jit-calls-stress,jit-inline-stress,jit-eager,jit-calls-eager,node`
   (add jit-no-hoist,jit-no-borrow once O2's passes are in), then `--self-test`
7. `python3 scripts/jit_kernels.py --rounds 7 --engines silkjs,silkjs-jit,silkjs-jit-calls,v8-jit,jsc-jit`
8. `silk test src/tests.silk -o build/core-tests --optimization speed --debug false` (2 known failures)

Rules that came out of merging: streams merge each other's reported heads before handing over;
shared encodings (exit state, call block, CompiledEntry layout, site bits: 42 ALWAYS, 43 lazy
arguments, 44-47 multi-result) are announced to the affected threads first; `inlinable` is a
whitelist; `silk check --no-server` when a check looks stale. Julia's standing rules: no pull
request unless she asks; interpreter-only cost under 0.5 percent; AOT stays possible (no
addresses in code or storable data); x86-64 first, arm64 later; Opus implements from detailed
plans, Fable optimizes from goals and measurements; never mention Rune; no model identifiers in
commits.
