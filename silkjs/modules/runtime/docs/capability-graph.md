# Capability graph

Generated by `silk task graph` in `tools/capabilities` (step 0 of [the composable runtime](composable-runtime.md)).
Do not edit by hand. Which service owns each built-in, native function and Silk module is a first cut by
name, in `tools/capabilities.toml`; moving a file between services is a change there, and this report is
what to read before making it.

## Edges across service lines

A require or native call from one service into another that is not among its declared needs
(`[[need]]` in `tools/capabilities.toml`, the pairs `embed.start` will check). Each is a decision for step 2: move the
piece to the core, turn it into a registration the capability makes when it loads, or declare the need.
Load-time edges block an empty service outright; lazy ones fail only on the path that takes them.
